# Proposal

## Why

Planning in this module was driven by Agent OS (`agent-os/standards/`, `.claude/commands/agent-os/`, `.roo/skills/`), an unversioned copy of rules that are now published as pinned OpenSpec stores (`quality`, `repository`, `terraform`). The module already holds OpenSpec content from the `production-ready-module` change, but its four main specs were written in delta format (`## ADDED Requirements`) and fail `openspec validate --strict`, and several statements in them no longer match the code. Moving to OpenSpec fully gives one planning system, a validated baseline contract and a CI check.

## What Changes

- Replace Agent OS by the referenced stores: remove `agent-os/standards/` (14 files), `.claude/commands/agent-os/` and `.roo/skills/`; the standards are consumed from the `quality`, `repository` and `terraform` stores pinned in `openspec/config.yaml`. Nothing is ported: the stores supersede the copies.
- Rewrite the four existing main specs (`input-validation`, `lifecycle-management`, `resource-timeouts`, `runtime-checks`) into main-spec format and drop or correct what the code does not do: the `ignore_tags_changes` variable (does not exist), security group timeouts (not applied), the `update` timeout on block volumes (not applied), and the port/port-range and security-group exclusivity rules, which are `validation` blocks (moved to `input-validation`) rather than preconditions.
- Add the baseline capabilities describing the module as released: `module-contract` and one capability per functional area.
- Add `AGENTS.md`, `CLAUDE.md`, `openspec/config.yaml` context and rules, `scripts/openspec-setup.sh`, the `validate:specs` CI job and the `spec-validate` / `spec-setup` mise tasks; the OpenSpec skills are installed for Claude Code and OpenCode.
- No change to any `.tf` file, input, output or resource: semver **patch**. `CHANGELOG.md` stays generated by git-cliff from commit subjects.

## Capabilities

### New Capabilities
- `module-contract`: tooling and provider constraints, no provider/backend blocks, inputs and defaults, naming and tags, project resolution, outputs.
- `instances`: expansion of instance groups into servers, attributes, tags, user data / cloud-init, backup snapshots.
- `security-groups`: shared and per-group security groups, rule merging, selection per server, outputs.
- `networking`: public IPs, IP outputs, private network attachment.
- `storage-volumes`: additional SBS and local volumes, external volumes, volume outputs.
- `placement-groups`: shared, existing and per-group placement groups.
- `ssh-keys`: optional IAM SSH key.

### Modified Capabilities
- `input-validation`: adds the project name, instance count, security-group exclusivity and port/port-range rules (ADDED requirements only; the existing ones were rewritten in place).

## Impact

- Removed: `agent-os/`, `.claude/commands/agent-os/`, `.roo/skills/`.
- Added: `AGENTS.md`, `CLAUDE.md`, `scripts/openspec-setup.sh`, `.gitlab/specs.yml`, `openspec/specs/*/spec.md` (on archive).
- Modified: `openspec/config.yaml`, `mise.toml`, `.gitlab-ci.yml`, `.gitlab/global.yml`, README "Contributing".
- Contributors register the stores once per machine (`mise run spec-setup`); CI only validates `openspec/`.
- Module consumers: none.
